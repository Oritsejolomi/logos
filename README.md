# Logos

**Bible & theology trivia, generated fresh every time.**

Every question is generated by Gemini 2.5 Flash on demand, then passed through three
accuracy gates before you see it. Every answer is followed by a scripture-grounded
insight so the game teaches you something even when you miss. The aesthetic is a
pinball hall of fame: all-time highest single-game scores, no accounts, just your
name on the board.

## How the accuracy gates work

Gemini is good but not infallible. Four layers of defense before a question reaches a
player:

1. **Static citation validator.** Every scripture reference is parsed and checked
   against a hardcoded map of the 66 Protestant canon books and their actual chapter
   and verse counts. A hallucinated citation like `Hezekiah 17:4` is rejected
   instantly at generation time — no Gemini needed.
2. **LLM-as-judge second pass.** A second Gemini call at low temperature reviews the
   generated question, options, claimed correct index, and citation. Verdicts:
   `correct` / `wrong_answer` (with `corrected_index`) / `wrong_citation` / `ambiguous`.
   Anything that isn't `correct` is rejected or auto-corrected.
3. **RAG against the real Bible text.** The judge call includes the actual verse text
   (World English Bible, public domain, stored as 31,095 rows in Postgres) so the
   check is grounded in scripture rather than the model's memory.
4. **Early skepticism for new questions.** Established questions need 3 player flags
   to be soft-deleted. Brand-new questions (played ≤ 3 times) soft-delete on the
   very first flag. Bad questions never get a chance to taint the bank.

There's also an option-quality check that rejects questions whose options contain
parenthetical definitions or echo distinctive words from the question stem, because
those are the two most common ways Gemini gives away the answer.

Sola scriptura: the system prompt explicitly forbids denominational distinctives,
extra-biblical tradition, and any claim that can't be pinned to a specific verse.

## Stack

- **Frontend:** Vite + React 18 + TypeScript + Tailwind CSS, deployed to Cloudflare
  Pages.
- **Backend:** Supabase only — Postgres, Realtime (broadcast channels + CDC), and
  Edge Functions (Deno).
- **AI:** Gemini 2.5 Flash via REST inside Edge Functions. 1M token context window
  used to pass prior-question exclusion lists for cross-session diversity.
- **Bible corpus:** World English Bible, public domain, loaded once from
  api.getbible.net into a `bible_verses` table.
- **Identity:** None. A `player_uuid` lives in `localStorage`, username is chosen
  on first visit and remembered across visits.

Everything server-side runs inside Supabase. No separate server to manage.

## Architecture at a glance

```
Client (React SPA)
  │
  ├──▶ Edge Functions (Deno, stateless)
  │     ├── create-solo-session      ── pre-fills queue from bank
  │     ├── get-question             ── serves from queue, falls back to Gemini
  │     ├── queue-solo-questions     ── parallel Gemini + gates for remaining slots
  │     ├── submit-answer            ── transactional scoring + play_count++
  │     ├── post-score               ── validates against theoretical max
  │     ├── get-leaderboard
  │     ├── create-room              ── multiplayer
  │     ├── join-room
  │     ├── start-game
  │     ├── submit-category-pick
  │     ├── start-room-questions
  │     ├── tick-room                ── any client drives the clock idempotently
  │     ├── get-mp-question
  │     └── submit-mp-answer
  │
  ├──▶ Supabase Postgres
  │     ├── questions                ── generated questions, permanently cached
  │     ├── solo_sessions            ── per-player game state
  │     ├── rooms                    ── multiplayer game state
  │     ├── room_players / room_answers
  │     ├── scores                   ── append-only hall of fame
  │     ├── question_flags           ── community moderation
  │     ├── bible_verses             ── WEB, 31,095 rows, used by RAG gate
  │     └── gemini_errors            ── observability
  │
  └──▶ Supabase Realtime
        ├── Postgres CDC  on rooms / room_players / room_answers
        └── Broadcast     on room:<code> for round_closed reveals
```

## Running locally

```bash
git clone <repo>
cd logos
npm install

# Set up .env.local with your Supabase project
cp .env.local.example .env.local  # (create your own — see below)

# Run the frontend
npm run dev
# → http://localhost:5173
```

`.env.local` needs:

```
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_ANON_KEY=<your-anon-key>
```

## Deploying the backend

```bash
# Link to your Supabase project
supabase link --project-ref <project-ref>

# Apply schema
supabase db push

# Deploy Edge Functions
supabase functions deploy

# Set secrets (Gemini API key)
# Do this once via the Supabase dashboard:
#   Project Settings → Edge Functions → Secrets
#   GEMINI_API_KEY=<your-key>

# Load the World English Bible corpus (one-time)
SUPABASE_URL=... SUPABASE_SERVICE_ROLE_KEY=... node scripts/load-bible.mjs
```

## Contributing

Logos is open source. If you spot a bad question, flag it in-game. If you want to
improve the gates, the prompts, the UI, the scoring, or the word-echo validator,
open a PR.

High-value contribution targets:

- **Better question diversity.** The avoid-list is currently capped at the last 200
  passages and 500 full question texts. There's room to be smarter about embedding
  distance or topic clustering.
- **More gates.** The current stack catches citation errors, option giveaways, and
  obvious wrong answers. There's more to catch around historical accuracy, Hebrew/Greek
  word meanings, and cross-book consistency.
- **Alternative Bible translations.** Right now the RAG gate uses the WEB because
  it's public domain. Adding KJV, ESV, or NIV as optional sources would help catch
  translation-specific framings.
- **Accessibility.** Keyboard navigation, screen reader labels, color contrast on
  the oxblood accent, and reduced-motion support for the timer bar.
- **Internationalization.** Every question is currently English-only. Spanish,
  French, Portuguese, Swahili, Korean would all be valuable.
